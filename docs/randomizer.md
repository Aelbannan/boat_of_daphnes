# Randomizer

Boat of Daphnes plays seeds made by the Wind Waker Randomizer, [wwrando](https://github.com/LagoLunatic/wwrando) by
LagoLunatic (MIT licence). wwrando decides where every item goes; this port generates the seed with wwrando's own
generator, then applies wwrando's changes to the game as it runs. You do not patch a disc or make a separate build
for each seed.

The player-facing flow follows Ship of Harkinian's randomizer menus: a quest choice on the file-select screen,
generating from the menu, a check tracker. The code is this project's own.

## The idea

wwrando normally writes a new, patched disc image (game id `GZLE99`). The port instead splits what wwrando does
into three kinds of change, by how they depend on the seed:

| Kind | Examples | How it reaches the game |
| --- | --- | --- |
| The same for every seed | wwrando's code patches (the replaced chest actor, new code in free space, two added modules) | Translated once, into the game module as a **mod variant**. The module contains both the vanilla code and wwrando's, and a switch picks one. |
| Depends on the options | Swordless, Hero Mode, remove music, invert compass, and about twenty more instruction words | **Option sites**: each is a pair of instructions picked by a switch (`rando_no_<option>`), set when a seed turns that option off. |
| Depends on the seed | The item at each of about 320 locations; the starting items, hearts and magic; entrances, charts and hints in the stage, event and text files | **Seed hooks** and **data writes** from the seed pack (items and start state), and an **overlay** of patched game files (the rest). |

For the seed-dependent items the host patches 45 code sites whose instruction holds an item id (a native hook runs
after the instruction and rewrites the register from the seed pack) and 42 bytes in item tables, plus the game
variables of wwrando's custom symbols (starting gear, hearts, magic, sword mode). The lists are generated by
`scripts/rando/variant_sites.py` from `scripts/rando/seed_sites.json`, which `scripts/rando/classify_patch.py`
makes by comparing wwrando's output across many seeds and option sets (`scripts/rando/patch_matrix.py`).

## What you need

- A module built with the randomizer variant: `python scripts/windows/build.py DISC --rando-variant`. It adds
  about a third to the compile time. See [building.md](building.md).
- The generator's runtime: `python scripts/windows/rando_runtime.py`. It fetches an embeddable Python 3.12 (wwrando
  needs 3.12), pinned wheels, wwrando's sources at a pinned revision (from a checkout named by `BOD_WWRANDO`, or
  downloaded) and gclib. Everything is checked against pinned hashes, and the result goes to
  `build/windows/rando_runtime/`, which a build copies into the app's `rando/` folder. After that it runs offline.
- Your own disc, for the patched game files.

wwrando's images and sources are fetched on your machine and are not part of this repository.

## Generating a seed

**Randomizer** in the settings menu has wwrando's options on pages (General, Locations, Item Modes, Entrances,
Hints, Tweaks, Starting Items). The menu is built from a description of wwrando's own option table
(`scripts/rando/describe_options.py`), so it follows wwrando. Options that wwrando hides or marks unbeatable are
hidden, and `randomize_enemies` is not supported.

Press **Generate** on the General page, or choose it from the file-select menu. A blank seed name becomes ten
random digits. The generator runs in its own process:

1. `scripts/rando/generate_seed.py` runs wwrando's generator without a disc (a dry run) and writes the seed pack and
   wwrando's logs into `Randomizer/<seed>/`.
2. `scripts/rando/patch_game.py` runs wwrando's patcher on your disc, but instead of writing an image it writes
   every game file wwrando changed (stage, event and text files, the banner) into `Randomizer/<seed>/overlay/`.
   This takes about fifteen seconds.
3. A one-file copy of the seed pack, `Randomizer/<seed>.json`, is written so you can send it to someone.

A **seed pack** is `seed.json` (schema `bod.seedpack`, version 1): the item at each location, the options, the
starting gear, the seed hash (the two names shown on the name-entry screen), wwrando's permalink and the commit of
the generator. The spoiler log and the non-spoiler log are written beside it, unless "do not generate a spoiler
log" is on.

You can also load a seed someone sent you: drop its `seed.json` (or its spoiler log) on the game window at the file
select, or use **Load Seed File** on the General page. The overlay is rebuilt from the permalink on your disc.

## Playing

On the file-select screen, choosing an empty file opens a quest choice, **Vanilla** or **Randomizer**, changed with
the D-pad or stick. Each has its own title logo. Choosing Randomizer shows:

- **Start Randomizer**: starts a new file with the loaded seed.
- **Generate New Randomizer Seed**: runs the generator ("Generating..." on screen, then a chime, or an error tone).
- **Open Randomizer Settings**: opens the menu at the Randomizer header.
- With no seed loaded, a message says to generate or drop a seed.

The screens are drawn by the app over the game's file-select scene, in the game's own colours and layout, and
driven by the game pad. The game's own sounds play through a hook on the file select (hook 50 in
[game-code-map.md](game-code-map.md)). Randomizer files show their quest and seed hash on the list, and a randomizer
file's plate is tinted.

### Switching in place

Choosing a quest does not restart the game. The host turns the randomizer on or off while the game runs:

- It switches the module's chunks between vanilla and wwrando's code (trampolines in the variant).
- It applies or undoes the seed's data writes and the option switches, remembering what the memory held.
- It mounts the seed's overlay of game files, and wwrando's title logo.
- It asks the game to run `cCc_Init` again, so the game rebuilds its table of dynamic modules (wwrando's code keeps
  a larger one, empty until this runs; with it empty no REL loads).

An older module without the variant's trampolines cannot do this; the app then restarts the game into the chosen
mode and returns to the file select by itself.

### Saves

Randomizer files and vanilla files share one memory card, `Save/GZLE01.card`. wwrando's game reuses event bits, so
the app records which seed each file belongs to in a sidecar, `Save/Randomizer.slots.json`: per file, the seed's
folder name, the two hash names, an identity (a hash of the permalink and the generator's commit) and the build
that made it. A file with no entry is a vanilla file.

If a file was made by a build whose randomizer save format or wwrando release is different, the card and the
sidecar are renamed `<name>-<time>.bak` (never deleted) at launch and you are told, as Ship of Harkinian does for
an outdated save. A file started from a seed always loads that seed.

### Your own settings in a seed

A few options belong to you, not the seed, and apply to any seed: Remove Music, Invert Sea Compass, and switch
targeting. The app sets them at load.

The Bunny Hood from the port's enhancements can be an extra item in a seed's pool, or a starting item. wwrando
knows nothing of it, so the generator adds it as one more non-progress item, and its flag rides on the permalink as
a `~BH` suffix.

## Check Tracker

**Randomizer > Check Tracker** (hotkey F4) opens a window that lists every location in the seed in play, grouped by
area (the Sea Chart's islands, then the dungeons, then the sea). Each location shows as:

| State | How it is known |
| --- | --- |
| Collected | The save's flag for that location is set: a chest was opened, an item picked up, a salvage or boss reward taken. `scripts/rando/check_flags.json` says which bit each location sets. |
| Collected (judged from your items) | A gift or shop item with no flag of its own, when its item is the only one of its kind in the seed and your save holds it. |
| Reachable now | wwrando's own logic says you can get there with what you have. |
| Not reachable yet | The logic says you cannot. |
| Skipped | Marked by you; kept per seed and file in `Save/CheckTracker.json`. |

Reachability comes from a helper process, `scripts/rando/check_logic_server.py`. It rebuilds the seed with wwrando's
logic (same permalink, so the same entrances, charts and required bosses), then answers one JSON request per line:
the items you have, in wwrando's names, in; the reachable locations out. The tracker asks again each time your items
change. Dungeon keys are counted from the checks you have collected, because the save only holds the unused ones.

Options in the page: hide collected, show only reachable, show non-progress locations, hide skipped, tint reachable
checks green, a text size and a background colour. When a teammate's save arrives through Anchor, checks that turn
collected in the next few seconds are shown as a teammate's. See [anchor.md](anchor.md).

## Scripts

| Script | Job |
| --- | --- |
| `scripts/windows/rando_runtime.py` | Fetches and verifies the generator's runtime (`--check` verifies only). |
| `scripts/rando/generate_seed.py` | Seed pack and logs from options and a seed or permalink. |
| `scripts/rando/patch_game.py` | wwrando's patched game files from your disc, without writing an image. |
| `scripts/rando/describe_options.py` | wwrando's option table as JSON, for the menu. |
| `scripts/rando/prepare_extras.py` | On first launch: the randomizer variant's RELs and the other files made from your disc. |
| `scripts/rando/variant_sites.py` | The variant's option sites, seed hooks and host tables, from a reference run. |
| `scripts/rando/patch_matrix.py`, `classify_patch.py` | Run wwrando over many seeds and options and sort its changes into the three kinds above. |
| `scripts/rando/translate_patched.py`, `check_variant.py` | Translate wwrando's patched code and check the variant's module layout. |
| `scripts/rando/make_check_flags.py` | Makes `check_flags.json` from the stage files. |
| `scripts/rando/check_logic_server.py` | The Check Tracker's reachability helper. |
| `scripts/rando/build_seed.py` | The older route: a separate build for one seed, one executable. Slow; kept as a fallback. |
| `scripts/rando/e2e_peeks.py`, `list_chests.py` | Test helpers; see [testing.md](testing.md). |

## Limits

- The seed pack and the variant are tied to one pinned wwrando release. A new release moves every offset: the
  site lists must be regenerated and the variant translated again.
- `randomize_enemies` is not supported.
- The module must have been built with `--rando-variant`. A module without it cannot play seeds.
